## 한 줄 개요 (직접 작성)

정수 배열에서 **더해서 목표값이 되는 서로 다른 두 원소의 인덱스**를 찾는 문제.

## 입력 규모 메모 (복잡도 판단용)

배열이 꽤 커질 수 있어(수만 개 수준) **O(n)** 해법을 목표로 한다. (정확한 제약은 위 링크 참고)

## 함수 시그니처 (풀 형태)

| 언어 | 시그니처 |
|------|----------|
| Python | `def twoSum(self, nums: List[int], target: int) -> List[int]` |
| C++ | `vector<int> twoSum(vector<int>& nums, int target)` |
| C | `int* twoSum(int* nums, int numsSize, int target, int* returnSize)` |

> C 에서는 반환 배열을 `malloc` 으로 할당하고, 길이를 `*returnSize` 에 담아야 합니다.

## 힌트 (접근 방향, 직접 작성)

1. 가장 단순한 방법: 이중 반복문으로 모든 쌍을 확인 → O(n²)
2. 더 빠르게: **해시맵**에 "이미 본 값 → 인덱스" 를 저장하면서, 현재 값에 대해 `target - 현재값` 이 맵에 있는지 한 번만 확인 → O(n)

## 추천 알고리즘 한눈에 보기

| 우선순위 | 알고리즘 | 추천도 | 시간 | 공간 | 왜 추천하는가 |
|----------|----------|--------|------|------|---------------|
| 1 | **해시맵 1-pass** | ⭐⭐⭐ | O(n) | O(n) | 배열을 한 번만 보면서 필요한 짝을 바로 찾을 수 있다. |
| 2 | 브루트 포스 | ⭐ | O(n²) | O(1) | 가장 직관적이지만 입력이 커지면 느리다. |
| 3 | 정렬 + 투 포인터 | ⭐ | O(n log n) | O(n) | 값의 합 찾기에는 좋지만, 원래 인덱스를 보존해야 해서 번거롭다. |

> 이 문제에서는 **해시맵 1-pass**를 기본 풀이로 추천합니다.
> `target - 현재값` 을 이미 본 적이 있는지만 확인하면 되기 때문입니다.

## 복잡도 요약

| 풀이 | 시간 복잡도 | 공간 복잡도 | 핵심 이유 |
|------|-------------|-------------|-----------|
| **해시맵 1-pass** | **O(n)** | **O(n)** | 각 원소를 한 번씩 보고, 해시맵 조회/저장을 평균 O(1)에 수행한다. |
| 브루트 포스 | O(n²) | O(1) | 가능한 모든 두 수 조합을 직접 확인한다. |
| 정렬 + 투 포인터 | O(n log n) | O(n) | 정렬 비용이 들고, 인덱스 보존을 위해 값-인덱스 쌍이 필요하다. |

## 해시맵 풀이 시각 자료

```text
nums = [2, 7, 11, 15], target = 9

i=0, 현재값=2
필요한 값 = 9 - 2 = 7
map = {}
→ 7 없음, 2를 저장
map = {2: 0}

i=1, 현재값=7
필요한 값 = 9 - 7 = 2
map = {2: 0}
→ 2 있음, 정답 = [0, 1]
```

## 알고리즘 특징

- 해시맵에는 **이미 지나온 값**만 저장합니다.
- 현재 값과 짝이 되는 값 `target - nums[i]` 를 먼저 찾고, 없으면 현재 값을 저장합니다.
- 같은 원소를 두 번 쓰면 안 되므로, 저장보다 조회를 먼저 하는 흐름이 안전합니다.
